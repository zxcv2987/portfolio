# AI Portfolio Build Prompt

아래 지시를 포트폴리오 사이트를 생성하는 AI 도구에 전달합니다.

---

`design-brief.md`, `site-requirements.md`, `profile.md`, `experience`, `case-studies`, `projects` 폴더의 Markdown 파일을 읽고 프론트엔드 개발자 포트폴리오 사이트를 구현해 주세요.

## 가장 중요한 원칙

- 제공된 경력, 프로젝트, 수치와 기술을 사실의 기준으로 사용합니다.
- 제공되지 않은 성과, 사용자 수, 기간, 팀 구성, 기여도, 기술 선택 이유를 만들지 않습니다.
- `TODO`가 있는 항목은 화면에 그대로 노출하지 말고 데이터가 확정될 때까지 숨깁니다.
- 문장을 줄일 수는 있지만 의미와 사실을 변경하지 않습니다.
- 디자인을 위해 콘텐츠를 과장하거나 마케팅 문구로 바꾸지 않습니다.

## 구현 기술

- Astro
- TypeScript
- Tailwind CSS
- Astro Content Collections (Markdown 또는 MDX)
- 정적 생성 우선
- Vercel 배포 가능 구조

## 디자인 방향

- 기술 문서처럼 읽기 쉬운 포트폴리오
- 흰색 또는 절제된 중립 배경
- 넓은 여백
- 명확한 제목과 본문 계층
- 성과 수치를 타이포그래피로 강조
- 과도한 그라데이션, 글래스 효과, 둥근 카드, 장식 애니메이션 금지
- 터미널을 모방한 디자인 금지
- 모바일에서 긴 본문이 읽기 쉬워야 함

## 홈 구성

1. 이름, 역할, 한 문장 소개
2. 대표 수치
   - 빌드 시간 5~10분 → 약 30초
   - 개발 피드백 속도 약 90~95% 개선
3. 회사 경력
4. 대표 사례
   - 관리자 시스템 리뉴얼
   - 기기 판별 로직 개선
5. 대표 프로젝트
   - 동글
   - 전남 청년 문화복지카드
6. 기타 프로젝트
   - 코펫
   - 빈차
7. 기술과 연락처

## 상세 페이지

각 상세 페이지는 다음 순서를 기본으로 사용합니다.

1. 한눈에 보기
2. 역할과 범위
3. 문제 상황
4. 판단과 제약
5. 구현
6. 결과
7. 회고
8. 관련 링크

모든 본문을 카드 안에 넣지 말고 일반 문서 레이아웃을 사용합니다. 요약과 핵심 수치에만 제한적으로 강조 영역을 사용합니다.

## 1차 작업 범위

먼저 실제 콘텐츠를 연결하기 전에 정보 구조, 라우팅, 공통 레이아웃, 타이포그래피를 구현합니다. 그다음 Markdown 파일을 연결합니다.

완료 후 다음 항목을 검토합니다.

- 모바일 반응형
- 시맨틱 HTML
- 키보드 탐색
- 메타데이터
- sitemap
- 이미지가 없는 상태에서도 어색하지 않은 레이아웃
- 불필요한 클라이언트 컴포넌트
- AI가 임의로 추가한 사실이 없는지
