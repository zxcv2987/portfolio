# Portfolio Design Brief

## 목표

운영 도메인을 이해하고, 서비스 운영 중 발견한 문제를 구조적으로 해결해온 프론트엔드 개발자로 보여야 합니다.

화려한 개인 브랜딩보다 경력과 기술적 판단이 빠르게 읽히는 문서형 포트폴리오를 목표로 합니다.

## 방문자가 첫 화면에서 알아야 할 내용

1. 프론트엔드 개발자라는 점
2. 실무 경력이 있다는 점
3. 관리자 시스템 빌드 시간을 약 10분에서 약 30초로 개선했다는 점
4. 화면 구현뿐 아니라 문제 분석, 데이터 정합성, 테스트, 배포까지 경험했다는 점
5. 상세 사례를 바로 열어볼 수 있다는 점

## 핵심 인상

- 차분함
- 논리적임
- 실무 중심
- 기술 선택의 근거가 명확함
- 과장하지 않음
- 운영과 실패 상황을 함께 고려함

## 시각 방향

- 밝은 배경 또는 절제된 다크 모드
- 넓은 여백과 읽기 쉬운 본문 폭
- 강한 제목 계층
- 성과 수치는 카드보다 타이포그래피로 강조
- 프로젝트 이미지는 장식보다 설명 자료로 사용
- 데스크톱과 모바일 모두 긴 기술 문서를 읽기 쉬운 구조

## 피해야 할 디자인

- 과도한 그라데이션
- 모든 내용을 둥근 카드에 넣는 구성
- 글래스모피즘과 그림자 남용
- 계속 움직이는 배경과 스크롤 애니메이션
- 터미널 화면을 흉내 낸 전형적인 개발자 포트폴리오
- 기술 로고를 의미 없이 많이 나열하는 구성
- AI가 임의로 만든 수치와 경력
- 프로젝트 상세를 랜딩 페이지 한곳에 전부 펼치는 구성

## 사진

개인 사진은 필수가 아닙니다. 사용한다면 얼굴이 분명하게 보이는 단정한 사진을 작은 크기로 배치합니다. 현재 사진보다 경력과 성과가 먼저 보이도록 구성합니다.
